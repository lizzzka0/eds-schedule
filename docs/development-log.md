# Дневник разработки EDS Schedule

**Проект:** Сервис электронного расписания Екатеринбургской духовной семинарии

**Дисциплина:** Объектно-ориентированное программирование

**Репозиторий:** https://github.com/lizzzka0/eds-schedule

**Дата актуализации:** 24.11.2026

## 1. Назначение проекта

Разрабатывается веб-сервис электронного расписания занятий Екатеринбургской духовной семинарии.

Приложение предусматривает пользовательскую часть для просмотра расписания и административную часть для управления учебными занятиями.

Проект разрабатывается с применением объектно-ориентированного подхода. Архитектура предусматривает разделение клиентской и серверной частей.

## 2. Выбранные технологии

| Компонент | Технологии |
|---|---|
| Клиентская часть | React, TypeScript, Vite |
| Серверная часть | NestJS, TypeScript, Node.js |
| Обмен данными | REST API, HTTP, JSON |
| База данных (планируется) | PostgreSQL |
| ORM (планируется) | Prisma |
| Тестирование backend | Jest |
| Тестирование frontend | Vitest, React Testing Library |
| Контроль версий | Git, GitHub |
| Среда разработки | Visual Studio Code |

Исходный код размещён в одном GitHub-репозитории с отдельными каталогами `frontend` и `backend`.

### Этап 2. Реализация первого серверного модуля

Создан модуль `lessons`, предназначенный для работы с учебными занятиями.

Реализованы следующие классы:

- `Lesson` — представляет учебное занятие, содержит его основные характеристики.
- `LessonsService` — предоставляет метод `findAll()` для получения списка занятий.
- `LessonsController` — обрабатывает HTTP-запросы к модулю занятий.

Создан маршрут `GET /api/lessons`, возвращающий демонстрационные данные в формате JSON.

В `main.ts` настроен CORS для локального frontend.

**Применённые элементы ООП:** классы, конструкторы, типизированные свойства, модификаторы доступа, методы, разделение ответственности и внедрение зависимостей.

### Этап 3. Тестирование серверной части

Настроено модульное тестирование с помощью Jest.

Проверены:

1. Создание стандартного контроллера приложения.
2. Создание сервиса `LessonsService`.
3. Получение списка учебных занятий.
4. Создание контроллера `LessonsController`.
5. Вызов сервиса контроллером и возврат данных.

**Результат:** 3 набора тестов, 5 тестов — успешно пройдены.

Проведена проверка работоспособности REST API через браузер.

Во время разработки обнаружены и устранены следующие проблемы:

- Конфликт порта `3000` (`EADDRINUSE`) из-за одновременного запуска нескольких экземпляров backend.
- Лишняя интеграция NestJS Observe, вызывавшая сообщения об ошибках инструментирования.
- Временная ошибка HTTPS-соединения при отправке коммита на GitHub.

После исправлений API продолжил работать, тесты прошли успешно.

**Коммит:** `4a6589e` — «Реализация модуля учебных занятий, REST API и модульных тестов».

### Этап 4. Подключение frontend к backend

В клиентской части созданы:

- Интерфейс `Lesson` для типизации данных.
- Функция `fetchLessons()` для получения расписания через HTTP.
- React-компонент `App`, отображающий полученные занятия.

Для асинхронной работы использованы `fetch`, `async/await`, `Promise`, `useEffect` и `useState`.

Предусмотрены состояния загрузки, ошибки и пустого расписания.

Стандартная страница Vite заменена первоначальным интерфейсом электронного расписания.

**Результат:** React успешно получает демонстрационные данные из NestJS и отображает занятие на странице.

Проведены проверки:

- `npm run build` — успешно.
- `npm run lint` — успешно.

## 4. Известные ограничения и незавершённые задачи

На текущем этапе расписание содержит только демонстрационные данные. Постоянное хранение информации ещё не реализовано.

Предстоит выполнить:

- Проектирование полной объектной модели и UML-диаграмм.
- Подключение PostgreSQL и Prisma.
- Реализацию учебных групп, подгрупп, преподавателей, дисциплин и аудиторий.
- Разработку пользовательских фильтров и переключения учебных недель.
- Создание административной панели и авторизации.
- Проверку конфликтов занятий.
- Экспорт расписания в формате iCalendar.
- Обеспечение доступности интерфейса, включая использование клавиатуры, экранных дикторов, масштабирование и контрастность.
- Автоматизированное тестирование frontend и интеграционные проверки.
- Размещение готового приложения на хостинге.

При удалении NestJS Observe npm сообщил о 23 уязвимостях в дереве зависимостей backend. Требуется отдельно изучить отчёт `npm audit` и выбрать безопасные обновления без принудительного изменения основных версий.

### Тестовые сценарии

| ID | Проверяемый сценарий | Ожидаемый результат |
|---|---|---|
| FT-01 | Успешное получение расписания | Отображаются дисциплина, преподаватель и аудитория |
| FT-02 | Ожидание ответа сервера | Отображается сообщение о загрузке |
| FT-03 | Ошибка получения данных | Отображается сообщение об ошибке |
| FT-04 | Получение пустого списка занятий | Отображается сообщение об отсутствии занятий |

Для имитации различных ответов серверной части использованы методы `mockResolvedValue()`, `mockReturnValue()` и `mockRejectedValue()`.

Тестирование выполняется без обращения к реальному серверу, что позволяет независимо проверять поведение клиентского приложения.
