## 2. Методика тестирования

Для проверки базы данных используются положительные и отрицательные тестовые сценарии.

Положительные сценарии предусматривают выполнение корректных операций с данными.

Отрицательные сценарии предусматривают намеренное нарушение установленных ограничений.

Отрицательный тест считается успешно пройденным, если PostgreSQL отклоняет операцию и возвращает ожидаемый код ошибки SQLSTATE.

Автоматизация тестирования реализована с использованием PL/pgSQL:

- DO — выполнение анонимного программного блока.
- DECLARE — объявление переменных.
- EXCEPTION — обработка исключений.
- GET STACKED DIAGNOSTICS — получение диагностической информации.
- RAISE NOTICE — вывод результатов тестирования.
- RAISE EXCEPTION — сообщение о нарушении ожидаемого поведения.

Тестовые данные создаются непосредственно во время выполнения скрипта и удаляются после успешного завершения проверок.

## 7. Обнаруженные проблемы и их устранение

### 7.1. Прерванная транзакция

При первоначальном ручном тестировании возникла ошибка SQLSTATE 25P02.

Причиной являлось выполнение последующих SQL-команд после возникновения ошибки внутри незавершённой транзакции.

Для устранения проблемы использовалась команда ROLLBACK.

В дальнейшем тестовые сценарии были автоматизированы с использованием блоков обработки исключений PL/pgSQL.

### 7.2. Особенности PostgreSQL 18

При выполнении теста DB-11 обнаружено несоответствие ожидаемого и фактического кодов SQLSTATE.

Первоначально скрипт ожидал код 23503 при попытке удаления записи, связанной с другой таблицей посредством внешнего ключа с правилом ON DELETE RESTRICT.

В PostgreSQL 18.6 при выполнении данной операции был получен код 23001.

Для устранения проблемы в тестовый скрипт добавлено определение версии PostgreSQL и выбор соответствующего ожидаемого кода ошибки.

После внесения изменений тест DB-11 успешно пройден.

Структура базы данных и ограничения целостности не изменялись, поскольку проблема находилась в логике тестового сценария.
